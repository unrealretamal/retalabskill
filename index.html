Turn UI reviews into fast, actionable interface improvements

`guide` gives you a clear set of design rules, `review` gives you a prioritized fix list. The examples below show "before/after" comparisons for the same business goal, making the differences visual: clearer primary tasks, more restrained hints, complete states, and more discoverable actions.

Core Rules (Condensed)

Not aiming for exhaustive — just the rules that produce the most stable results: pass these 6 first, then refine visuals.

6 Rules Shared by Dev & Review
1) Primary task firstMain action identifiable in 3 seconds
2) Layered help textNearest essential info first, expand on demand
3) State coverageLoading/empty/error/success/permission — each shows next step
4) Spacing scale4/8/12/16/24/32/40/48
5) Repetition & alignmentSame component type = same spacing, no drift
6) Minimal nestingContainers must have a function — no decorative wrapping
If a rule needs lots of exceptions, check information architecture and default values first, before adding more help text.
Suggested order: pass core rules first → design psychology diagnosis → fill in states & details (icons/motion).

Micro-Interaction & Error Patterns

Slips vs mistakes: different causes demand different fixes.

Slip

User knows what to do but accidentally does something else — e.g. clicks wrong chip, deletes wrong item.

Fix: undo, confirmation for destructive actions, adequate tap targets, clear visual distinction between similar items.

Undo available for 5 seconds
Mistake

User forms wrong goal or wrong plan — e.g. picks "hourly" when "daily" was the right choice, enters email in the wrong field.

Fix: constraints, smart defaults, preview before confirm, clear labels with examples.

This action will delete all data. Type "DELETE" to confirm.
